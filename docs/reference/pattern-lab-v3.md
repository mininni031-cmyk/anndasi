## 1. プロジェクトの目的

PATTERN LABは、株式チャートの形状認識、過去の類似パターン検索、統計検証、リスク管理、仮想売買を統合した個人向け投資研究・練習アプリである。

中心となる体験は以下。

1. 株式チャートを表示する
2. 過去の類似チャートを検索する
3. A〜Dの4つの理論から評価する
4. 統計的な根拠と想定損失を確認する
5. 買付・売却・見送りを判断する
6. PAPERモードで仮想取引する
7. 結果を記録し、判断の質を検証する

利益の保証や自動売買の推奨は行わない。

**最優先原則：取引しない判断も正しい行動として扱う。**

既存PC、電気代、インターネット接続費、将来の実株購入代金は0円の対象外とする。

## 4. 対象市場・時間足

### 対応対象

- 日本株
- 米国株
- 短期：1分・5分・15分足
- 中期：1時間・日足
- 長期：週足・月足

データ構造は両市場に対応させるが、最初からすべての時間足を実装しない。

**初期動作確認：日本株の日足、米国株の1分足。**

### 市場データ取得方針

優先順位：

1. 架空OHLCVデータを生成して開発する
2. ユーザーのCSVを取り込む
3. 公式の無料APIを条件に応じて追加する
4. 取得できないデータは「利用不可」と表示する

日本株はJ-Quants、米国株はAlpacaを接続候補とする。

無料プランの対象期間、利用資格、配信範囲、レート制限、保存・再配信条件は導入時に公式規約を再確認する。

日本株の無料分足データが確保できない場合、無理にスクレイピングせず、CSVインポートで対応する。

## 5. チャートパターン検索エンジン

### 入力

- 選択した銘柄
- 時間足
- 直近20本のローソク足
- 始値・高値・安値・終値・出来高

### 類似度計算

初期の重み付け：

- 20本全体の形状：50%
- 最後のローソク足：25%
- 直近3本の組み合わせ：15%
- 値幅・出来高：10%

価格を正規化し、過去区間との重み付き距離を計算する。

重みは暫定値であり、最適値とはみなさない。

### 自動パターン認識

初期対象：

- ダブルボトム
- ダブルトップ
- ヘッドアンドショルダー
- 逆ヘッドアンドショルダー
- 三角持ち合い
- 主要なローソク足パターン

判定は「形成中」「成立確認」「否定」「判定不可」に分ける。

### 検索結果

右側に類似度上位5件を表示する。

各結果には銘柄、日時、類似度、ミニチャート、パターン名、5・10・20本後の騰落率を持たせる。

未来情報はリプレイ開始時には非表示とする。

形状類似度は将来の上昇確率として使用しない。

## 6. A〜D評価エンジン

### A｜テクニカル型

トレンド、支持線、抵抗線、移動平均線、出来高、チャートパターンの成立条件を確認する。

出力：強気候補／弱気候補／方向不明／データ不足。

### B｜クオンツ型

類似事例数、期待損益、コスト控除後の結果、信頼区間、未使用期間での再現性を評価する。

出力：検証基準達成／未達／根拠不足／未検証。

未来情報の混入、過剰最適化、生存者バイアスを防ぐ仕組みを持つ。

### C｜企業・イベント型

決算発表や重要イベントと、その公表日時を確認する。

出力：イベントあり／通常日確認済み／未確認。

初期版では情報が不足する場合に「未評価」を認める。架空の企業分析結果を生成しない。

詳細業績・財務分析は後期追加。

### D｜リスク管理型

買付余力、保有数量、損切り価格、想定損失、日次損失上限、注文内容を検査する。

出力：条件内／修正必要／注文禁止。

**Dの安全条件は、A〜Cの評価より優先する。**

A〜Dの多数決で自動的に買いを決定してはならない。

## 7. RISK GUARD

### 絶対に注文禁止

- 買付余力不足
- 注文数量・売買単位の不正
- 保有数量を超える現物売却
- 事前設定の損失上限違反
- 注文データの不整合
- 重大なデータ異常

### 厳格モードで注文禁止

- 事前設定した戦略条件の未成立
- 統計的根拠の不足
- 検証に必要なデータ不足
- 事前設定した評価基準の未達

### 警告表示

- 相場環境の不一致
- パターンが形成中
- 決算情報未確認
- 類似事例の少なさ
- 約定精度の限界

通常モードと厳格練習モードを切り替え可能にする。

新規注文の禁止によって、既存保有株のリスクを減らす売却が不必要に妨げられないようにする。

## 8. PAPER仮想売買エンジン

### 初期設定

- 仮想初期資金：100万円
- 現物取引を基本とする
- 空売り・信用取引は初期対象外
- 日本株の銘柄別売買単位に対応
- 成行・指値・逆指値に対応
- 仮想口座はリセット可能
- 手数料・スリッページを設定可能

### 売買操作

1. 注文入力
2. RISK GUARDの確認
3. 仮想注文を受付
4. 過去または架空の相場データで約定判定
5. 保有数量・現金残高を更新
6. 売却時に実現損益を計算
7. 取引ジャーナルへ記録

### 注文状態

DRAFT / BLOCKED / ACCEPTED / OPEN / PARTIALLY_FILLED / FILLED / CANCELLED / EXPIRED / REJECTED

### 損益管理

- 現金残高
- 注文拘束資金
- 保有株数
- 売却可能株数
- 平均取得単価
- 実現損益
- 評価損益
- 総資産
- 日次損益
- 最大ドローダウン
- 取引コスト

売却は部分売却と全売却の両方に対応。

注文IDによる二重約定防止、残高と株数の整合性を必須とする。

金額は固定精度で処理し、浮動小数点による資金計算の誤差を避ける。

## 9. 売買ジャーナル

以下を自動保存する。

- 取引日時
- 銘柄・時間足
- 買付・売却・見送り
- 注文価格・数量・約定価格
- A〜Dの評価
- RISK GUARDの判定
- 売買理由
- 実現・評価損益
- ルール遵守状況

見送り判断も記録し、その後の値動きを振り返る。

ただし、結果だけで過去の判断を正解・不正解と決めない。

## 11. データの正確性と研究

参考文献には、Lo・Mamaysky・Wangのチャートパターン認識研究、Brockらのテクニカル売買ルール研究、Park・Irwinのレビューなどを利用する。

文献の理論を採用するときは、出典、実装上の近似、検証結果を記録する。

必須の検証方針：

- 過去から未来への時系列評価
- 開発・調整・最終評価データの分離
- ランダム戦略等との比較
- 手数料・スリッページの考慮
- 利益が出なかった事例の表示
- 同じ条件での結果再現
- 統計的な不確実性の表示

研究結果が不十分な場合は「根拠不足」と表示する。

## 12. LIVE実株購入への将来拡張

初期版では実注文機能を実装しない。

将来的に以下の順で拡張する。

1. 証券APIの利用条件・法規制・市場データ権利を確認
2. 読み取り専用で残高と保有株を取得
3. 注文照会と状態同期を検証
4. 発注直前の安全確認を実装
5. 本人の明示承認による実注文を追加

PaperBrokerとLiveBrokerAdapterを分離する。

実注文では認証情報の保護、二重発注防止、通信障害時の照会、緊急停止、監査ログを必須とする。

APIの利用条件が満たせない場合は、無理に連携しない。

## 14. 禁止する開発行為

Codexは以下をユーザーの明示承認なしに行わない。

- 有料APIの契約
- 有料サービスの追加
- クラウドサーバーの契約
- 有料データ購入
- 実株注文の送信
- 証券APIトークンの外部送信
- 市場データの無断再配信
- 既存プロジェクトの変更
- 未検証の投資成績を事実として表示

実装が困難な場合は、機能を削除せず「未実装・制約あり」と記録し、無料で実現可能な代替手段を提案する。

## 15. 完成の定義

PATTERN LABのPAPER版は、次の一連の流れが正常に動いた時点で基本完成とする。

**チャート確認 → 過去類似検索 → A〜D評価 → RISK GUARD → 仮想購入または見送り → 保有 → 売却 → 損益と判断理由の検証。**

初期版はインターネット接続がなくても、ローカルに保存した市場データで主要機能を利用できる。

最終目標は利益を約束することではない。

**市場データと複数の理論を比較して、自分で根拠を持って判断できるようになること。そして、取引しない判断も含めて検証できること。**
